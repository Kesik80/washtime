# WashTime Таймер для стиральной машины, сушилки и посудомойки. Progressive Web App без сборки: один HTML-файл, отдельный словарь переводов и несколько serverless-функций на Vercel. Главная задача — получить уведомление о том, что машина закончила, **даже если телефон заблокирован, а браузер закрыт**. Для этого используется Web Push через VAPID и отложенная доставка через QStash, а не таймер в браузере. --- ## Возможности - **Три машины** — стиральная, сушильная, посудомойка. Каждую можно скрыть с экрана; запущенная показывается всегда. - **Отложенный старт** — таймер считает от заданного времени старта, а не от нажатия кнопки. Рядом кнопка «сейчас». - **Программы** — свой список для каждой машины: добавление, удаление, редактирование длительности, температуры и расхода, избранное на карточке, сброс к заводским. - **Уведомления** — Web Push, Telegram или оба сразу. Работают при заблокированном экране. - **Напоминание о белье** — повторное уведомление через заданное время после окончания цикла, отдельно для каждой машины. - **Профили и «семья»** — несколько человек делят одни машины, состояние синхронизируется через Firebase Realtime Database. - **Статистика** — количество циклов, расход воды и электричества, стоимость по своим тарифам, история запусков (последние 500). - **Погода** — прогноз через Open-Meteo и подсказка, когда лучше сушить бельё на улице. - **Резервная копия** — выгрузка всех настроек в JSON и загрузка обратно. - **4 языка** — русский, украинский, немецкий, английский. - **Offline** — service worker кэширует статику; установка на домашний экран в полноэкранном режиме. - **Темы** — светлая, тёмная, автоматическая. --- ## Стек | Слой | Технология | |---|---| | Клиент | `index.html` — vanilla JS, без сборки и зависимостей | | Переводы | `lang.js` — отдельный словарь на 4 языка | | Хостинг | Vercel (статика + serverless функции) | | База | Firebase Realtime Database | | Отложенные задачи | Upstash QStash | | Push | Web Push (VAPID), `web-push` | | Telegram | Bot API | | Погода | Open-Meteo, геокодинг — Nominatim (OSM) | Сборки нет намеренно: проект правится и деплоится с телефона через веб-интерфейс GitHub. --- ## Структура ``` . ├── index.html # всё приложение: разметка, стили, логика ├── lang.js # словарь переводов (ru / uk / de / en) ├── sw.js # service worker: кэш + push + локальные уведомления ├── console.js # отладочный оверлей консоли для мобильной разработки ├── vercel.json # маршруты и заголовки ├── package.json ├── icons/ │ ├── manifest.json │ ├── icon-192.png │ └── icon-512.png ├── svg/ │ ├── man.svg │ └── woman.svg └── api/ ├── firebase-config.js # отдаёт клиенту конфиг Firebase ├── vapid-config.js # отдаёт публичный VAPID-ключ ├── push-subscribe.js # сохраняет подписку устройства в Firebase ├── push-schedule.js # ставит отложенный push в очередь QStash ├── push-send.js # отправляет push (вызывается QStash по таймеру) ├── schedule.js # ставит отложенное Telegram-сообщение в QStash ├── notify.js # отправляет сообщение в Telegram └── debug.js # проверка конфигурации ``` **Порядок подключения важен:** `lang.js` идёт в `` до основного скрипта, `console.js` — последним перед ``. Если `lang.js` не загрузится, приложение не упадёт, но покажет имена ключей вместо текста. --- ## Как работают уведомления Ключевая идея: браузер не должен быть открыт в момент срабатывания. ``` Нажатие «Запустить» │ ├──► /api/push-schedule ──► QStash (отложенная задача) │ │ │ ждёт до времени окончания │ │ │ ▼ │ /api/push-send │ │ │ читает подписку из Firebase │ │ │ web-push + VAPID │ │ │ FCM / Mozilla │ ▼ │ sw.js → showNotification │ └──► /api/schedule ──► QStash ──► /api/notify ──► Telegram ``` Подписка устройства создаётся при первом запуске и сохраняется в Firebase под ключом `deviceId` из `localStorage`. Напоминание о белье планируется тем же способом, но на время окончания плюс заданная задержка. ### Важно: приоритет сообщения `push-send.js` отправляет push с заголовком `Urgency: high`: ```js await webpush.sendNotification(subscription, payload, { urgency: 'high', TTL: 3600 }); ``` Без этого заголовка push-сервис Chrome передаёт сообщение в FCM с обычным приоритетом, и в режиме Doze (экран выключен) доставка откладывается до пробуждения устройства. Уведомление приходит с задержкой в десятки минут или только когда пользователь сам разблокирует телефон. Это самая частая причина «push не работает». --- ## Установка ### 1. Клонировать и установить зависимости ```bash git clone https://github.com/Kesik80/washtime.git cd washtime npm install ``` ### 2. Firebase 1. Создать проект в [Firebase Console](https://console.firebase.google.com). 2. Включить **Realtime Database**. 3. Задать правила на вкладке **Rules**: ```json { "rules": { ".read": false, ".write": false, "families": { "$familyId": { ".read": true, ".write": true } }, "pushSubscriptions": { "$deviceId": { ".read": true, ".write": true, ".validate": "newData.hasChildren(['subscription', 'deviceId'])" } } } } ``` > **Не оставляйте правила в тестовом режиме.** Firebase создаёт их в виде `"now < 1775599200000"` — через 30 дней база начинает отвечать `permission_denied`, подписки перестают сохраняться, и push молча перестаёт работать. Ошибка при этом видна только в консоли браузера. ### 3. VAPID-ключи ```bash npx web-push generate-vapid-keys ``` Публичный ключ отдаётся клиенту через `/api/vapid-config`, приватный остаётся в переменных окружения. ### 4. QStash Зарегистрироваться в [Upstash](https://upstash.com), создать QStash и скопировать токен. ### 5. Telegram (необязательно) Создать бота через [@BotFather](https://t.me/BotFather), получить токен. `TELEGRAM_CHAT_ID` можно узнать через `https://api.telegram.org/bot/getUpdates`. ### 6. Переменные окружения В Vercel → Settings → Environment Variables: | Переменная | Назначение | |---|---| | `FIREBASE_DB_URL` | URL Realtime Database | | `FIREBASE_API_KEY` | Web API key проекта | | `FIREBASE_APP_ID` | App ID | | `VAPID_PUBLIC_KEY` | публичный VAPID-ключ | | `VAPID_PRIVATE_KEY` | приватный VAPID-ключ | | `VAPID_EMAIL` | контакт в формате `mailto:you@example.com` | | `QSTASH_TOKEN` | токен Upstash QStash | | `INTERNAL_SECRET` | общий секрет для внутренних вызовов API | | `TELEGRAM_BOT_TOKEN` | токен бота (если нужен Telegram) | | `TELEGRAM_CHAT_ID` | ID чата для сообщений | ### 7. Деплой Подключить репозиторий к Vercel — сборка не требуется, деплой идёт по каждому коммиту. > `vercel.json` использует старый формат `routes` без `"handle": "filesystem"`. Это значит, что **каждый статический файл нуждается в собственном маршруте**. Добавляешь новый файл в корень — добавь и маршрут, иначе получишь 404. --- ## API | Метод | Endpoint | Назначение | |---|---|---| | `GET` | `/api/firebase-config` | конфиг Firebase для клиента | | `GET` | `/api/vapid-config` | публичный VAPID-ключ | | `POST` | `/api/push-subscribe` | сохранить подписку устройства | | `POST` | `/api/push-schedule` | запланировать push | | `POST` | `/api/push-send` | отправить push (вызывает QStash) | | `POST` | `/api/schedule` | запланировать Telegram | | `POST` | `/api/notify` | отправить в Telegram | | `GET` | `/api/debug` | проверка конфигурации | --- ## Хранение данных **localStorage** (на устройстве): | Ключ | Содержимое | |---|---| | `laiS2` | всё состояние: профили, машины, программы, настройки, история | | `washDeviceId` | идентификатор устройства для push | | `washFamilyId` | идентификатор общей «семьи» | | `washLangManual` | выбранный вручную язык | | `washMelody` | мелодия сигнала | | `washNotifMode` | режим уведомлений: `push` / `tg` / `both` | | `laiConsole` | показывать ли отладочную панель | **Firebase Realtime Database** (общее): ``` families/{familyId}/members/{deviceId} профили участников families/{familyId}/machines/{key} состояние машин pushSubscriptions/{deviceId} подписки на push ``` **Резервная копия.** Настройки → Данные → «Сохранить настройки» выгружает всё состояние в JSON. `deviceId` намеренно не выгружается: он привязан к устройству, и восстановление чужого id сломало бы адресацию push. --- ## Offline и кэш `sw.js` кэширует статику по стратегии «сеть, затем кэш»: онлайн всегда приходит свежая версия, офлайн открывается последняя сохранённая. Запросы к `/api/` и внешним сервисам не кэшируются никогда — ответы одноразовые, а погода и подписки должны быть актуальными. **При изменении статики поднимай константу `CACHE` в `sw.js`.** Старые кэши удаляются в `activate`, иначе пользователь останется на прошлой версии. Это же защищает от рассинхрона `index.html` и `lang.js`. Версия сборки видна в Настройки → О приложении и пишется в console.js при запуске — по ней проверяется, обновилась ли установленная PWA. --- ## Разработка с телефона Проект писался и правится без компьютера, отсюда несколько особенностей. `console.js` — самодельный оверлей консоли: показывает ошибки, сетевые запросы и тайминги прямо в приложении, потому что DevTools на Android недоступны. Подключается последней строкой перед ``: ```html ``` Отключается в Настройки → Данные → «Показывать консоль». Весь клиент лежит в одном файле специально: правка через веб-редактор GitHub работает без инструментов, а Vercel деплоит по коммиту. ### Грабли, на которые уже наступали - **Затенение функции `t()`.** Локальная переменная или параметр с именем `t` перекрывает функцию перевода, и код падает в рантайме. `node --check` этого не ловит — синтаксис корректен. Дважды ломало приложение: сначала таймер, потом погоду. - **Вызов `t()` внутри словаря.** Массовая замена строк на `t('key')` однажды попала и в сам `lang.js`; словарь начал вызывать функцию, которая читает этот же словарь, и весь скрипт умирал при загрузке. - **Абсолютные пути к ресурсам** (`/svg/man.svg`) ломаются, если приложение открыто не из корня домена — например, в локальном превью по подпути. --- ## Известные ограничения - **`INTERNAL_SECRET` попадает в клиент** при вызове `/api/push-schedule`, то есть защита эндпоинтов условная: посторонний может слать уведомления и тратить квоту QStash. - **Доступ к базе без аутентификации.** Кто знает `familyId`, может читать и писать в её узел. - **Напоминание нельзя отменить** после планирования: QStash не позволяет отозвать сообщение без хранения его идентификатора. - **`updateAll` перезаписывает DOM каждую секунду**, даже когда значения не изменились. - **Виджет на домашний экран невозможен** — веб-API для виджетов Android не существует, нужна нативная обёртка. - **Закрыть установленную PWA из кода нельзя** — `window.close()` для неё заблокирован. - **Web Push не работает в iOS Safari** вне установленной на домашний экран PWA. --- ## Диагностика **Push не приходит:** 1. Открыть приложение и проверить в console.js строку `Push ✓ подписка сохранена на сервере`. Если вместо неё ошибка 500 — смотреть правила Firebase. 2. Проверить в Firebase → Data узел `pushSubscriptions` — там должна быть запись с вашим `deviceId`. 3. Убедиться, что в `push-send.js` задан `urgency: 'high'`. 4. На Xiaomi, Samsung и Huawei снять ограничения батареи и включить автозапуск для приложения и для Chrome — фирменные «оптимизаторы» гасят фоновые процессы независимо от настроек Android. **Уведомления приходят только когда приложение открыто** — почти всегда это отсутствующий `Urgency: high` либо ограничения батареи производителя. **Приложение показывает старую версию** — сравнить версию в Настройки → О приложении с последней сборкой. Если отличается, поднять `CACHE` в `sw.js` или очистить кэш приложения в настройках Android. --- ## Лицензия MIT
