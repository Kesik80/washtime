# LaundryAI

Таймер для стиральной машины, сушилки и посудомойки. Progressive Web App на одном HTML-файле плюс несколько serverless-функций на Vercel.

Главная задача — получить уведомление о том, что машина закончила, **даже если телефон заблокирован, а браузер закрыт**. Для этого используется Web Push через VAPID и отложенная доставка через QStash, а не таймер в браузере.

---

## Возможности

- **Три машины** — стиральная, сушильная, посудомойка. Каждую можно скрыть с экрана.
- **Отложенный старт** — таймер считает не от нажатия кнопки, а от заданного времени старта.
- **Программы посудомойки** — 7 предустановок с длительностью, температурой, расходом воды и электричества.
- **Уведомления** — Web Push, Telegram или оба сразу. Работают при заблокированном экране.
- **Профили и «семья»** — несколько человек делят одни машины, состояние синхронизируется через Firebase Realtime Database.
- **Статистика** — количество циклов, расход воды и электричества, стоимость по своим тарифам, история запусков.
- **Погода** — прогноз через Open-Meteo и подсказка, когда лучше сушить бельё на улице.
- **4 языка** — русский, украинский, немецкий, английский.
- **Offline** — service worker и установка на домашний экран.
- **Темы** — светлая, тёмная, автоматическая.

## Стек

| Слой | Технология |
|---|---|
| Клиент | Один файл `index.html` — vanilla JS, без сборки и зависимостей |
| Хостинг | Vercel (статика + serverless функции) |

## Как работают уведомления

Ключевая идея: браузер не должен быть открыт в момент срабатывания.

```
Нажатие «Запустить»
        │
        ├──► /api/push-schedule ──► QStash (отложенная задача)
        │                              │
        │                    ждёт до времени окончания
        │                              │
        │                              ▼
        │                       /api/push-send
        │                              │
        │              читает подписку из Firebase
        │                              │
        │                    web-push + VAPID
        │                              │
        │                        FCM / Mozilla
        │                              ▼
        │                    sw.js → showNotification
        │
        └──► /api/schedule ──► QStash ──► /api/notify ──► Telegram
```

Подписка устройства создаётся при первом запуске и сохраняется в Firebase под ключом `deviceId` из `localStorage`.

### Важно: приоритет сообщения

`push-send.js` отправляет push с заголовком `Urgency: high`:

```js
await webpush.sendNotification(subscription, payload, {
  urgency: 'high',
  TTL: 3600
});
```

Без этого заголовка push-сервис Chrome передаёт сообщение в FCM с обычным приоритетом, и в режиме Doze (экран выключен) доставка откладывается до пробуждения устройства. Уведомление приходит с задержкой в десятки минут или только когда пользователь сам разблокирует телефон. Это самая частая причина «push не работает».

## Установка

### 1. Клонировать и установить зависимости

```bash
git clone https://github.com/Kesik80/washtime.git
cd washtime
npm install
```

### 2. Firebase

1. Создать проект в [Firebase Console](https://console.firebase.google.com).
2. Включить **Realtime Database**.
3. Задать правила на вкладке **Rules**:

```json
{
  "rules": {
    ".read": false,
    ".write": false,
    "families": {
      "$familyId": { ".read": true, ".write": true }
    },
    "pushSubscriptions": {
      "$deviceId": {
        ".read": true,
        ".write": true,
        ".validate": "newData.hasChildren(['subscription', 'deviceId'])"
      }
    }
  }
}
```

> **Не оставляйте правила в тестовом режиме.** Firebase создаёт их в виде `"now < 1775599200000"` — через 30 дней база начинает отвечать `permission_denied`, подписки перестают сохраняться, и push молча перестаёт работать. Ошибка при этом видна только в консоли браузера.

### 3. VAPID-ключи

```bash
npx web-push generate-vapid-keys
```

Публичный ключ отдаётся клиенту через `/api/vapid-config`, приватный остаётся в переменных окружения.

### 4. QStash

Зарегистрироваться в [Upstash](https://upstash.com), создать QStash и скопировать токен.

### 5. Telegram (необязательно)

Создать бота через [@BotFather](https://t.me/BotFather), получить токен. `TELEGRAM_CHAT_ID` можно узнать через `https://api.telegram.org/bot<TOKEN>/getUpdates`.

### 6. Переменные окружения

В Vercel → Settings → Environment Variables:

| Переменная | Назначение |
|---|---|
| `FIREBASE_DB_URL` | URL Realtime Database |
| `FIREBASE_API_KEY` | Web API key проекта |
| `FIREBASE_APP_ID` | App ID |
| `VAPID_PUBLIC_KEY` | публичный VAPID-ключ |
| `VAPID_PRIVATE_KEY` | приватный VAPID-ключ |
| `VAPID_EMAIL` | контакт в формате `mailto:you@example.com` |
| `QSTASH_TOKEN` | токен Upstash QStash |
| `INTERNAL_SECRET` | общий секрет для внутренних вызовов API |
| `TELEGRAM_BOT_TOKEN` | токен бота (если нужен Telegram) |
| `TELEGRAM_CHAT_ID` | ID чата для сообщений |

### 7. Деплой

Подключить репозиторий к Vercel — сборка не требуется, деплой идёт по каждому коммиту.

## Хранение данных

**localStorage** (на устройстве):

| Ключ | Содержимое |
|---|---|
| `laiS2` | всё состояние: профили, машины, настройки, история |
| `washDeviceId` | идентификатор устройства для push |
| `washFamilyId` | идентификатор общей «семьи» |

| `washNotifMode` | режим уведомлений: `push` / `tg` / `both` |

**Firebase Realtime Database** (общее):

```
families/{familyId}/members/{deviceId}    профили участников
families/{familyId}/machines/{key}        состояние машин
pushSubscriptions/{deviceId}              подписки на push
```

## Разработка с телефона

Проект писался и правился без компьютера, поэтому есть пара особенностей.

`console.js` — самодельный оверлей консоли: показывает ошибки, сетевые запросы и тайминги прямо в приложении, потому что DevTools на Android недоступны. Подключается последней строкой перед `</body>`:

```html
<script src="console.js"></script>
</body>
```

При замене `index.html` эту строку легко потерять — без неё отладка вслепую.

Весь клиент лежит в одном файле специально: правка через веб-редактор GitHub работает без инструментов, а Vercel деплоит по коммиту.

## Известные ограничения

- **Расчёты в статистике неточные.** «Среднее время» считается по текущим настройкам машин, а не по истории. Показатель «в этом месяце» при пустом месяце показывает количество за всё время.
- **Доступ к базе без аутентификации.** Кто знает `familyId`, может читать и писать в её узел. Для домашнего использования приемлемо, для публичного — нужен Firebase Auth.
- **`INTERNAL_SECRET` частично попадает в клиент** при вызове `/api/push-schedule`, то есть защита эндпоинта условная.
- **История не ограничена по размеру** и со временем растёт в localStorage.
- **Web Push не работает в iOS Safari** вне установленной на домашний экран PWA.

## Диагностика

**Push не приходит:**

1. Открыть приложение и проверить в console.js строку `Push ✓ подписка сохранена на сервере`. Если вместо неё ошибка 500 — смотреть правила Firebase.
2. Проверить в Firebase → Data узел `pushSubscriptions` — там должна быть запись с вашим `deviceId`.
3. Убедиться, что в `push-send.js` задан `urgency: 'high'`.
4. На Xiaomi, Samsung и Huawei снять ограничения батареи и включить автозапуск для приложения и для Chrome — фирменные «оптимизаторы» гасят фоновые процессы независимо от настроек Android.

**Уведомления приходят только когда приложение открыто** — почти всегда это отсутствующий `Urgency: high` либо ограничения батареи производителя.
